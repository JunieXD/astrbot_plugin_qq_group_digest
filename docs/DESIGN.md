# 设计与接口边界

## 目标与结构

一条任务对应一个来源群，多个目标群共享同一期内容。定时读取 QQ 历史，无群消息监听器。任务名只用于展示，稳定进度标识由来源群与显式机器人绑定组成。

```mermaid
flowchart LR
    A[AstrBot 定时触发与恢复检查] --> B[创建固定时间窗口]
    B --> C[分页读取并保存短期快照]
    C --> D[独立模型提炼与来源校验]
    D --> E[摘要与目标投递计划原子落库]
    E --> F[共享操作队列]
    F --> G[提交意图落库]
    G --> H[OneBot 发送]
    H --> I[回执成功或结果待核对]
```

| 模块 | 职责 |
| --- | --- |
| `main.py` | 插件生命周期、私聊管理员入口。 |
| `config.py` / `_conf_schema.json` | 领域配置校验与中文配置界面。 |
| `schedule.py` / `service.py` | 时区、计划边界、恢复与流水线调度。 |
| `platform.py` | 连接身份、显式 `self_id`、QQ 查询额度和传输。 |
| `history.py` | 分页推进、时间筛选、去重、消息规范化与有限转发展开。 |
| `summarizer.py` | 独立上下文、分块提炼、逐层合并、结构与来源校验。 |
| `render.py` | 一份结构化摘要对应四种确定性展示。 |
| `delivery.py` | 按目标和分段投递、能力检查、有限历史核对。 |
| `store.py` | SQLite 事务、时间进度、输入快照、发送意图和滚动额度。 |
| `pacing.py` / `resources.py` | 共享队列兼容、日志轮转、跨进程实例锁。 |

平台 I/O、模型 I/O 与纯配置/排版逻辑分开，可独立测试。无需导入其他插件代码，部署时不依赖其目录结构。

## 对照源码确认的接口

核查对象为实现前本机实际安装的 AstrBot、NapCat，以及 QCE 6.2.6 对应源码。上游版本更新仍需要兼容性测试。

| 需求 | 已核对的实现 | 本插件的使用方式 |
| --- | --- | --- |
| 历史读取 | NapCat `get_group_msg_history` 首页调用 `getAioFirstViewLatestMsgs`，后续调用 `getMsgHistory/getMsgsIncludeSelf` | 现有 OneBot 连接上小页串行读取。 |
| 分页游标 | 参数名 `message_seq` 经短消息 ID 映射到原生 `msgId`；返回 `real_seq` 才是原生序号 | 不递减短 ID；每次执行重新从历史建立游标，长期保存时间边界。 |
| 消息解析 | `disable_get_url`、`parse_mult_msg`、`quick_reply` 可控制部分解析行为 | 不获取不必要的媒体地址，不自动深度展开。 |
| 模型生成 | AstrBot `Context.llm_generate` 与 `get_current_chat_provider_id` | 复用配置提供商，独立 system/user 上下文、无工具，不污染聊天会话。 |
| 消息投递 | `send_group_msg` / `send_group_forward_msg` 返回消息 ID | 使用 `bot.call_action` 保留回执，不把 `Context.send_message` 返回的布尔值当消息 ID。 |
| 合并转发能力 | `nc_get_packet_status` 成功返回空数据；能力不可用时检查失败 | 按调用是否成功判断，不能按返回值真假判断。 |
| 定时任务 | `cron_manager.add_basic_job` 支持时区，但处理函数只保留在内存，错过执行宽限有限 | 非持久触发器随生命周期重建；本插件数据库负责进度与补跑。 |
| 接入路由 | aiocqhttp 反向 WebSocket 根据 `self_id` 选择连接 | 明确指定账号；拒绝多个接入之间的歧义，记住任务实际绑定。 |

AstrBot 自带平台聊天历史有可配置的保留数量和内容转换规则，不能作为完整 QQ 历史来源。QCE 使用了更深层的原生序号分页接口；其能力不直接等同于标准 OneBot 历史接口。本插件无需 QCE，预留了清晰的历史读取边界以便以后替换实现。

参考项目：[AstrBot](https://github.com/AstrBotDevs/AstrBot)、[NapCatQQ](https://github.com/NapNeko/NapCatQQ)、[QCE 6.2.6 历史读取](https://github.com/shuakami/qq-chat-exporter/blob/v6.2.6/qq-chat-export-server/src/fetcher/batch_fetcher.rs)。

## 历史完整性

窗口使用 `[start,end)`，额外的时间重叠只作为上下文。按原生群序号去重，缺失时使用群、消息标识、时间、发送者及文本组合。分页必须向更早内容推进，不能用 `count` 是否取满推断是否到达时间边界。

NapCat 的消息 ID 缓存属于短 ID 映射，不等于历史记录的保留时长。重启后不持久复用这个游标。

解析失败、缺失标识、时间不合法、来源群不符、分页停滞和超过读取限制都会停止本期。NapCat 可能将原生消息解析后过滤成空数组，因此空页也不能直接证明已覆盖完整时段。缩短回溯范围有时可以恢复，但没有 API 能证明 QQ 的离线同步没有遗漏。

`parse_mult_msg=false` 并不能保证 NapCat 不获取转发内容；引用解析、成员信息补查也可能触发更多原生查询。本插件限制的是自身调用，不控制这些内部操作。图片、音视频和文件正文不属于首版摘要输入。

## 状态与投递

批次状态：`queued → fetched → generated → complete`；失败可进入 `failed`。新一期会把尚未读取的旧批次标记为 `superseded`，合并为有上限的补报。已经生成的摘要按目标保存进度，过期未提交投递会跳过。

投递状态：`pending → submitted → sent`；提交后异常或进程退出进入 `unknown`。提交前失败可以等待或进入 `blocked`。`skipped` 代表明确放弃，不代表已送达。

摘要和投递计划在同一事务中保存。发送意图与额度在同一事务中提交；数据库没有记录成功意图时不会调用发送。收到回执先保存消息 ID，再离开发送函数。未知发送不会自动重发；核对只接受机器人自己的唯一匹配内容，不通过“没找到”证明失败。

普通分条的后续部分不能越过同目标的未知部分。一个目标的异常不影响其他目标。配置变化在提交前重新检查：关闭/暂停阻止新发送，删除目标使其尚未完成的投递跳过，新增目标只影响新的批次。

QQ/OneBot 没有此用途的通用幂等发送键。因此采用保守的未知状态，不能宣称端到端 exactly-once。

## 模型与展示

低消息量只调用一次模型，高消息量分块后逐层合并。单条长消息分段输入，不直接丢弃尾部。模型输出必须符合 `items[{title,body,sources}]`，每条来源必须存在于当前输入，最终条目必须至少引用一条本期消息。

每次调用还要求返回与本次输入匹配的 `batch_id`。它只出现在该次用户输入里，用于拒绝输入在模型适配器超长重试中被丢弃后产生的无依据空结果，不展示给群成员。

结构校验不等于事实校验。相似但表达不同的信息可能仍重复，重要信息也可能被模型遗漏。先尝试一次格式修复，再由批次有限重试管理失败。每次调用与整期调用总数均有上限；本期计数和滚动日额度在同一事务中预约，重载与自动重试不重置，管理员手动重试只重置本期计数。不假设所有提供商都支持相同的结构化输出参数。

聊天正文被明确视为资料，无工具执行权限。模型不能选择目标群、控制调度或生成 OneBot 操作。输出使用显式文字段，避免 CQ 码注入；普通整篇过长时提示修改配置，不自动刷出很多条消息。

## 生命周期和验证

`initialize()` 获取数据目录实例锁、打开数据库、注册属于本插件的定时器；`terminate()` 清理定时器、等待后台任务取消和已提交事务完成，再关闭资源。即使调度器清理失败，也要停止工作任务。

共享协调器复用平台管理器上的既有对象，不替换其他插件的对象类型。独立安装时注册兼容的版本 3 协调器。账号锁使用既有协议的 platform ID，实际账号身份另行验证，避免同 QQ 多接入造成两条独立发送队列。

测试采用真实 SQLite 和可控的模拟接口。真实群聊历史覆盖范围、卡片在客户端的显示以及 QQ 最终接收结果，需要用户环境中的小范围验收。测试不会消耗模型额度或发送 QQ 消息。
