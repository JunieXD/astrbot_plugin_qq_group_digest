# QQ 群聊摘要

[![Checks](https://github.com/JunieXD/astrbot_plugin_qq_group_digest/actions/workflows/ci.yml/badge.svg)](https://github.com/JunieXD/astrbot_plugin_qq_group_digest/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

在你指定的时间，从 QQ 群历史消息中提取有用信息，用 AstrBot 已配置的模型生成摘要，再发送到来源群或多个目标群。

例如：每天 **06:00、18:00** 各整理一次群聊，把有价值的通知、截止时间、资料链接和讨论结论发到资讯群。

**默认关闭自动发送。** 不需要持续监听群消息，不需要安装聊天导出插件，不需要另填模型密钥或开新的接口端口。

## 安装与首次使用

要求：**AstrBot ≥ 4.26.2、< 5，Python ≥ 3.10，NapCat 的 OneBot v11 接入**。QQ 官方机器人 API 不适用。机器人需要加入来源群和所有目标群，并能在目标群发言。

1. 在 AstrBot 插件管理中，通过仓库地址安装：

   ```text
   https://github.com/JunieXD/astrbot_plugin_qq_group_digest
   ```

2. 打开插件配置，添加一条“摘要任务”。填写来源群、目标群、发送时间和关注内容。
3. 在 AstrBot 中配置好模型。任务的“使用哪个模型”留空时，跟随来源群的模型设置；也可以单独选择。
4. 使用 **AstrBot 管理员账号私聊机器人**：`/群摘要 预览 来源群号`。预览会使用模型额度，按该群配置的展示方式在私聊返回，不推进定时进度；配置为合并转发时，私聊收到同样排版的转发卡片。
5. 确认效果后开启“启用定时摘要”，保存并重载插件。首次自动摘要在下一个计划时间生成；希望立刻处理最近一期时，发送 `/群摘要 执行 来源群号`。

命令里的“来源群号”要替换为实际数字。这里的管理员指 AstrBot 配置中的管理员；仅有 QQ 群管理员身份不能操作这个插件。

私聊预览受理后会先回复“已收到”。历史按页读取且每页有等待，活跃群整理一天的消息可能需要数分钟，再加上模型生成时间。可用 `/群摘要 状态 来源群号` 查看读取页数、消息数、当前阶段和已用时间；不用重复发起预览。中途重载插件会取消正在进行的预览，需要重新发送命令。

历史查询默认缓存 **30 分钟**，预览和定时摘要共用。改提示词、换模型后再次预览，可以复用已完整读取的旧区间，补查新增消息和末尾一分钟；第一次仍需完整读取。模型结果按输入、提示词、模型及请求设置另行缓存，完全相同的已完成工作可复用。缓存不会无限续期，也不会把未读完的记录当成完整历史。

缓存期间，较早消息的撤回或变化可能暂未反映。需要完整重查时，发送 `/群摘要 预览 来源群号 刷新`。高级限制中的“历史查询缓存可复用几分钟”可设为 0 关闭，最多 120 分钟。缓存按机器人账号、接入、来源群和昵称采集设置隔离，重启后也可复用；不复用 NapCat 的旧翻页游标。合并转发正文单独缓存 30 分钟；新读到的转发会及时展开，缓存失效后会先恢复原消息定位，再展开。

## 配置很简单

一个来源群配置一条任务。同一份摘要可以发到多个目标群，不同来源群的时间、模型、关注内容和展示方式分别设置。

| 配置项 | 怎么填写 |
| --- | --- |
| 任务名称 | 例如“保研资讯”。修改名称会保留进度。 |
| 从哪个群提取信息 | 来源群号。 |
| 发到哪些群 | 每行一个目标群号。 |
| 同时发到来源群 | 只想发到别的群时关闭。 |
| 每天什么时候发送 | 每行一个 `HH:MM`，例如 `06:00`、`18:00`。 |
| 希望提取什么信息 | 用自然语言写关注与排除的内容；不用写 JSON 格式。 |
| 使用哪个模型 | 选择已有模型，或留空跟随来源群设置。 |
| 摘要如何展示 | 下表中的四种形式。 |
| 卡片外部标题 | 合并转发未点开时的标题，例如“✨ 保研情报站”；也用于会话消息预览。 |
| 正文顶部标题 | 点开后摘要最上方的标题，例如“今日保研精选”；普通消息也使用此项。 |

| 展示方式 | 群里看到什么 |
| --- | --- |
| 普通消息·整篇 | 一条包含全部摘要的普通文字消息。 |
| 普通消息·分条 | 按主题发送多条普通消息，每条之间有等待。 |
| 合并转发·整篇 | 一张可点开的转发卡片，里面一条完整摘要。 |
| 合并转发·分条 | **群里仍是一张卡片**，打开后按主题查看多个节点。 |

私聊预览与群内投递共用排版、随机发送间隔和发送额度；预览回复给发起命令的管理员，使用接收命令的机器人账号。长摘要按所选展示方式处理，不截断成普通文本；发送结果不明时停止后续分段，不自动重发或改发文本。

合并转发使用机器人的 QQ 身份，不冒用群成员身份。普通消息按文字发送，摘要中的 CQ 码不会被执行为真实提及或其他操作。

模型分别提炼“具体对象、关键进展、简短要点”，插件组合为“对象｜进展”标题和分点正文，不逐句摘抄；结合明确上下文还原指代，无法确定对象的零碎反馈会要求模型舍弃。

两个标题在每条任务的展示方式下方分别设置。各自留空时使用“✨ 任务名称 · 群聊摘要”（未填任务名称时使用群号）；自填内容原样显示，想保留 ✨ 就一起填入。均为最多 80 字的单行文字，不需要模板语法。保存并重载后，后续生成的预览和定时摘要使用新标题；已生成的投递计划保持原样。

卡片封面和正文标题下保留时间范围；主题按“编号＋短标题、空行、短要点”排版。正文保留群友署名、传闻和条件，不反复追加“未经核实”等套话。媒体识别限制、转发展开情况和预算省略数量只保留在后台，不显示为群里的说明消息。

关注内容示例：

> 关注计算机保研的夏令营、预推免通知、报名截止时间、材料要求和经验讨论结论。保留原始链接。忽略打卡、闲聊、广告和没有实质进展的重复信息。对于传闻，明确写出尚未确认。

如果希望保留有参考价值但尚未证实的群友说法，可在任务的“更多设置”中开启 **“引用群友说法时保留昵称”**，并在关注内容中写明：

> 保留有参考价值的个人反馈、招生偏好和门槛传闻。写成“群友‘某某’称：听说甲校卡 rk1”，保留适用学院、年份和原话的限定条件；听说和本人经历分开写，不当作院校政策。不同说法并列呈现，判断权交给读者。

署名优先取历史消息里的群名片，其次昵称；没有显示名时不猜测。不同成员的同名昵称、同一成员改名会在模型输入中区分。此开关默认关闭，开启后跨群摘要也会保留昵称。只通过历史接口取得显示名，不额外查询成员资料。转发内容单独标记，里面的署名不能证明真实身份，不能当作转发者本人的观点。最终措辞仍由模型生成，署名和限定条件应在预览时检查。

完整的示例配置见 [examples/config.json](examples/config.json)。里面的群号是示例，自动摘要保持关闭。

## 模型调用与记录

默认优先 **一次处理完整时间窗口**。输入使用紧凑消息记录和发言者代号，保留原文、精确到秒的时间、姓名变化和回复关系。消息及回复编号使用整数，发言者保持 `u` 前缀以免混淆；昵称由程序在输出时填入，避免模型从长表中抄错姓名。完整编辑规则只放一份，长记录末尾保留简短质量提醒；不为压缩而删除短句、条件、反例或链接。仅当超过模型预算时才分块；分块会优先补充被回复的消息和相邻上下文。

“模型输入字符上限”设为 **0** 自动适配：ECNU Max 使用官方 512000、Plus 使用 256000 tokens 上下文；其他模型默认使用 32000，可手动填写官方大小。手动填写字符上限时，它仍是独立的硬限制，可能使摘要提前分块。

ECNU Max 当前对应 DeepSeek-V4-Flash-0731，插件随附 [DeepSeek 官方 V4 离线分词器](https://api-docs.deepseek.com/quick_start/token_usage) 数据，通过 `tokenizers` 在本地计算提示词、聊天正文和 JSON Schema 的 tokens。无需联网下载、无需模型权重，也不执行远程代码。分词器不添加额外特殊 token、不截断文本；包内 `model_max_length=16384` 不作为 ECNU 的上下文限制。原始来源与校验值见 [分词器说明](qq_group_digest/assets/deepseek_v4/NOTICE.md)。

输入预算分别扣除你配置的输出上限（含思考）、256 tokens 对话格式余量，以及上下文的 2% 安全余量（至少 2048 tokens）。系统提示词单独计数，每一块用户输入按最终拼接后的完整文本核对，避免把 BPE 分词数简单相加。整个时间窗口能放下时只调用一次；超限才分块并补充回复上下文。发送模型请求前再次检查完整输入，预算不足不会提交请求。分词和分块在工作线程运行，避免阻塞其他插件。

只有已明确匹配 V4 的模型使用该分词器；ECNU Plus 和其他模型保留 UTF-8 字节保守预算。依赖或数据文件缺失、校验失败也会回退，并记录原因，绝不会按 0 tokens 放行。后台 `模型输入预算`、`模型调用开始` 日志记录计数方式、预算、预留及本地估算；调用记录、费用统计仍以接口返回的实际 `usage` 为准，不用本地估算冒充实际用量。

ECNU 请求通过独立的 AstrBot 适配器副本设置 JSON Schema、思考参数和输出上限，其他插件的模型设置不受影响。默认开启思考，程度为 `low`。开启思考时使用默认采样参数；关闭思考且未单独设置温度时使用 0.2。署名及 sources 引用本次输入中出现的发言者代号，程序恢复对应历史昵称；不存在的代号会被拒绝。这是发言者范围校验，不是逐句事实核验，模型仍可能理解错对象或限定条件；群友反馈保留署名及“听说、可能”等原有限定。成功的分块默认保存 60 分钟，输入、提示词、模型或请求参数变化会失效，失败重试不必重做成功分块。来源不合法、拒答、截断不会当作成功摘要发布。

结构化输出采用 [ECNU 官方推荐的 `response_format.type = json_schema`](https://developer.ecnu.edu.cn/vitepress/llm/api/structuredoutput.html)，约束 `items` 及每条的 `subject`、`title`、`body` 要点数组和 `sources`，禁止额外字段。Schema 固定且计入输入预算，不随群成员数量附带巨大的编号枚举；编号是否存在、署名、空内容和字数仍由本地校验。结构化输出只保证格式，不能保证信息正确，因此仍保留提示词中的语义要求与来源校验。正文不设置字符级解码上限，避免为满足格式截断条件或句子。

在插件配置的 **“模型生成设置（仅本插件）”** 中调整：

| 配置 | 默认值 | 用法 |
| --- | --- | --- |
| ECNU 结构化输出 | 开启 | 使用 JSON Schema 约束字段结构；关闭时退回 `json_object`，本地校验继续生效。 |
| ECNU 思考模式 | `enabled` | `enabled` 开启；`disabled` 关闭；`inherit` 跟随 AstrBot 共享模型设置。 |
| ECNU 思考程度 | `low` | Max：`low / high / max`；Plus：`low / medium / xhigh`。仅显式开启时覆盖档位。 |

预览、分块、合并和修正摘要使用相同设置；其他插件与非 ECNU 模型的请求不受影响。修改有效请求参数后不会复用旧模型结果，但仍可复用聊天记录缓存。新版本默认开启 `low`，包括升级后的原有配置。思考可能增加耗时和输出用量，可在高级限制中调整模型等待时间和输出 token 上限；输出截断时不会发布残缺摘要。

只解析并发送最终 `content`，不把 `reasoning_content` 当作摘要，也不保存思考正文；接口返回的思考 token 继续记入用量统计，并作为输出明细避免重复计费。参考 [ECNU 思考模式文档](https://developer.ecnu.edu.cn/vitepress/llm/thinking.html)。

LLM 统计参考群审核插件：记录每次请求和重试、模型、阶段、耗时、状态、具体校验原因、输入/输出/缓存/思考 tokens、原始 usage、费用与计价快照。缺失用量保留为未知；缓存明细不全时费用显示区间，不伪装成零消耗。ECNU 可配置峰谷 credits 价格。

默认保存模型输出、不保存完整聊天输入；可在“LLM 调用记录与费用统计”调整。内容有长度上限及截断标记，记录默认保留 90 天。统计写入失败不会阻断摘要。重启时尚未完成的记录标为中断，不据此重发请求。

管理员也可通过 AstrBot 的已认证插件接口调用 `POST /api/v1/plugins/extensions/qq_group_digest/preview`，请求 `{"group_id":"来源群号","refresh":false}`。接口运行同一预览链路，返回摘要、文字和按配置构造的消息载荷，**不会向 QQ 发送**；需要具有插件权限的 AstrBot OpenAPI 密钥。接口和私聊共享互斥及冷却。

## 时间范围与重启恢复

- 默认时区为 `Asia/Shanghai`。
- 首次默认读取计划时间之前最多 **24 小时**，可在每个任务的高级设置中调整。
- 以后按相邻计划时间统计。例如 18:00 那一期处理 `[06:00, 18:00)`；即使模型在 18:03 才生成，截止时间仍是 18:00。
- 每期（含首次生成和私聊预览）默认额外读取开始时间前 **10 分钟**作为上下文，只发布本期新增内容或更新。时间重叠可以关闭或调整；语义上的去重仍受模型能力影响。
- 没有值得发布的信息时静默完成，不发“本期无内容”。
- 重启后合并错过的时间段，默认最多补 **24 小时**。NapCat 离线期间尚未读取的旧批次会并入后续补报。
- 已生成但超过补报时长的待发送摘要会跳过，避免恢复后连续发布过期消息。已经提交但结果不明的发送保留待核对记录。
- 一期摘要生成后会保存。A 群成功、B 群失败时，A 群不会因 B 群重试而再收到一次。

关闭总开关、关闭单条任务、移除目标群或使用暂停命令，会阻止尚未提交的相应发送。已经发给 NapCat 的请求不能由插件撤回取消。更换来源群或明确更换机器人 QQ 会作为新任务开始；自动识别的机器人身份发生变化时会停止并提示检查绑定。

生成失败后，可以修改关注内容、模型、摘要长度和展示方式再重试，尚未生成的批次会采用最新配置，统计时间窗口保持不变。修改转发读取或昵称引用设置会重新读取历史；已经生成的摘要和发送计划保持固定。合并转发的“改发普通整篇”开关可用于已有但尚未提交的卡片。移除目标群只取消确定尚未提交的部分，待核对记录仍保留。

## 读取哪些内容

默认提取文字、文字中的链接，以及分享卡片里能解析的标题、描述和链接。引用会映射到本次模型输入中的消息编号；当前时间窗口之外的引用明确标为不可见，不会无限追查。

高级设置可开启“展开聊天中的合并转发”：只展开一层，默认每期最多 5 个转发，每个最多 100 个节点。转发内部旧消息作为本次转发的内容理解，所属期次按外层消息发布到群里的时间判断。

**首版不识别图片、不转写语音、不解析视频或文件正文、不自动打开网页。** 不可见的内容会保留占位说明；部分转发未展开等诊断保留在后台记录与预览接口返回数据中，不附加到群消息末尾。模型只拿到有限的可读取内容，不能保证提取出所有重要信息，重要截止时间请核对原文。

数据来自当前 QQ 客户端可读取的历史。被清理、无法同步或没有被账号接收的记录无法保证补回。成功翻页覆盖时间边界也不等于证明 QQ 历史毫无缺失。

## 失败时会怎样

| 情况 | 插件行为 |
| --- | --- |
| 读取失败、翻页停滞、空页无法判断覆盖范围、超过读取上限 | 不拿半份记录发布摘要；有限重试后停止该批次。 |
| 翻页途中 NapCat 重连 | 放弃本次读取，从第一页重新开始，不跨连接复用短消息 ID。 |
| 模型失败、JSON 或来源校验不通过、明确截断 | 不发布不完整输出；允许有限重试，保留已读取的短期快照。 |
| 某个目标群无法访问、禁言、发送准备失败 | 其他目标可以继续；该目标按原因等待或停止，状态中可查看。 |
| 合并转发能力不可用 | 默认暂缓。可开启“改发普通整篇”，只在提交前切换。 |
| 发送已经提交，随后超时、断线或进程退出 | 标记“待核对”，**不自动重发，不立即切换普通消息**。 |
| 多段中的一段结果不明 | 暂停该目标的后续分段，避免乱序；其他目标不受影响。 |
| 数据库不能写入 | 无法记录提交状态时不发消息；已提交但无法记录回执的请求需核对。 |

NapCat 合并转发在某些运行状态下会走“先给自己发送节点再合并”的备用路径。插件会检查 `nc_get_packet_status`，尽量避免这条隐式批量发送路径；平台内部状态和 QQ 的最终行为仍由 NapCat/QQ 决定。

QQ 发送接口没有通用的幂等键，无法承诺绝对不重不漏。待核对批次可通过命令在近期历史中找机器人自己发送的匹配内容；找不到不代表一定没发出。核对只查最近最多 60 条消息、最多 5 个转发内容，因此较早的结果可能无法自动确认。

## 私聊命令

| 命令 | 用途 |
| --- | --- |
| `/群摘要` | 帮助。别名 `/qgdigest`。 |
| `/群摘要 状态 [来源群号]` | 启用状态、下一计划时间及各目标进度；优先显示最早的 5 个未解决批次，再显示最近 3 期。处理后继续查看可见其余记录。 |
| `/群摘要 预览 来源群号` | 按配置的普通消息或合并转发样式生成私聊预览，不建立投递计划；同群至少间隔 60 秒。 |
| `/群摘要 预览 来源群号 刷新` | 绕过并替换历史缓存，完整重读后生成私聊预览。 |
| `/群摘要 统计 [来源群号] [天数]` | 默认最近 7 天的调用、状态、tokens、缓存命中、耗时和估算费用。 |
| `/群摘要 记录 来源群号` | 最近调用编号、模型、用量和具体校验问题。 |
| `/群摘要 详情 调用编号` | 单次调用详情和已保存的模型原始输出。 |
| `/群摘要 导出 来源群号 [天数]` | 私聊发送 CSV，含已开启保存的请求、响应、usage 和计价快照。 |
| `/群摘要 执行 来源群号` | 将最近计划期次交给队列；已处理过的期次不会重复建立。需要启用任务。 |
| `/群摘要 暂停 来源群号` | 暂停该来源群的自动处理；重载后仍有效。 |
| `/群摘要 恢复 来源群号` | 解除命令暂停；总开关和任务开关仍需开启。 |
| `/群摘要 重试 批次编号` | 恢复生成失败或发送准备失败的部分，不重发待核对请求。 |
| `/群摘要 核对 批次编号` | 只读查询目标群近期历史，唯一匹配时记录成功。 |
| `/群摘要 跳过 批次编号 [目标群号]` | 放弃该批次尚未完成的投递；省略目标群则作用于整批，也可跳过尚未生成或生成失败的批次。 |

批次编号从状态消息复制。跳过不删除群里的消息，也不宣称未知发送已经成功。

## 执行节奏与工程限制

高级设置中可以调整查询间隔、发送前等待、操作间隔、重连等待、连续失败冷却及滚动额度。默认每页读 100 条，查询间隔随机 1.5～3 秒；发送前等待 5～20 秒，自动操作间隔 8～20 秒。

默认每个机器人每小时最多 360 次插件查询、最近 24 小时最多 80 条摘要发送（含私聊预览正文）；全插件最近 24 小时最多 100 次模型调用，每期最多 32 次。自动重试和重载不会重置本期模型计数；管理员明确重试失败批次时才重置本期计数，日额度仍然保留。预览和核对也计入相应额度。一次模型调用内部可能有 AstrBot/模型服务自身的重试，ECNU 摘要禁用 SDK 的隐式重试，并关闭 AstrBot 在单次调用内切换密钥或删除上下文后重试的行为；其他适配器仍以各自实现为准。单次历史接口内部也可能有多次 QQ 查询；这些计数不是底层网络请求总数。

发送兼容 JunieXD 的群审核、成员清理、名片规范及 GitHub 订阅插件使用的共享操作协调器。没有这些插件时也能独立工作。模型生成不占用 QQ 发送队列。随机等待用于节流，**不能保证避免账号风控**。

查询超时或连接失败后，同一接入的其他查询也会等待冷却，重载不会清除等待。摘要排队和发送准备完成后还会复查有效期，避免长时间等待后继续投递过期内容。全部处于待核对状态的旧批次不会反复查询 QQ；非管理员的私聊命令不自动回复。

模型略超摘要字数或主题数时，按模型给出的价值顺序保留放得下的完整主题，并在后台记录省略数量；不截断句子、昵称、条件或来源。单个主题就超限时，最多一次定向改写。最终普通整篇太长、分段太多、历史超过上限时仍会明确停止。建议先增加每天的总结次数，缩短每期时间，再根据模型能力调整高级限制。

## 数据和日志

数据放在 AstrBot 的 `data/plugin_data/astrbot_plugin_qq_group_digest/`，与插件代码分开，更新代码不会清除进度。

- `state.sqlite3`：计划进度、短期输入快照、历史与转发缓存、成功分块、摘要、每个目标的回执与额度。
- `llm_usage.sqlite3`：模型调用记录、用量、可选请求与响应、费用及具体校验原因。
- `llm_exports/`：按需生成的 CSV，导出时清理超过一天的旧文件。
- `logs/digest.jsonl`：结构化运行日志，默认 **20 MiB 一个文件，保留 7 个旧文件加当前文件**；按大小轮转，不按日期删除。
- `instance.lock`：防止同一数据目录被多个实例同时运行。

输入快照默认保留 2 天，已完成摘要默认保留 30 天；定期清理。未完成和待核对状态保留，避免丢失恢复依据。SQLite 删除记录后可能复用已有文件空间，文件大小不一定立即缩小。

历史查询缓存默认 30 分钟后不再复用，写入缓存和每小时清理时删除过期条目；每个缓存范围只保留最新一份覆盖记录。改变提示词或模型不会清除原文缓存，模型摘要本身不进入这层缓存。

日志记录时间、群号、批次、数量、状态和错误类型，不写聊天原文、模型提示词、模型完整响应或密钥。生成摘要时，选中的聊天文字会发送给你配置的模型服务。可在高级设置调整保留时间和日志大小。
